# 평가 문항 12 · 장애 심각도와 예방

이번 실험 조건에서는 Deadlock이 가장 치명적이라고 판단합니다. OOM과 CPU 장애는 보호 정책에 의해 프로세스가 종료되므로 PID나 포트 소실로 비교적 쉽게 감지할 수 있습니다. 반면 Deadlock은 프로세스와 포트가 살아 있어 단순 liveness 검사를 통과하면서 실제 작업만 무기한 멈출 수 있습니다.

근본 예방 방법은 모든 코드 경로가 동일한 순서로 락을 획득하도록 규칙을 정하는 것입니다. 여기에 lock timeout, `try_lock`, 실패 시 rollback을 적용하고 단순 생존 검사가 아닌 작업 진행 여부를 확인하는 readiness 검사를 둡니다.

다만 메모리 제한이나 보호 정책이 없는 운영 서버라면 OOM이 노드 전체를 중단시킬 수 있으므로 실제 심각도는 장애의 영향 범위와 복구 가능성을 함께 보고 결정해야 합니다.
