# 평가 문항 13 · 복합 장애 대응

OOM과 Deadlock이 동시에 의심되면 다음 순서로 대응합니다.

1. 재시작 전에 PID, RSS, 스레드 상태, 마지막 로그를 짧게 보존합니다.
2. 트래픽을 다른 인스턴스로 우회해 추가 영향을 막습니다.
3. 서버 전체로 확산될 수 있는 메모리 압박을 먼저 완화합니다. 메모리 증가 프로세스를 제한하거나 필요하면 종료합니다.
4. 노드가 안정된 뒤 보존한 스레드 대기 상태와 A↔B 락 로그로 Deadlock을 분석합니다.
5. 각각 별도 조건으로 다시 재현해 원인을 분리합니다.

메모리 고갈은 같은 노드의 모든 프로세스와 진단 도구까지 영향을 줄 수 있으므로 안정화 우선순위가 더 높습니다. 단, 증거 없이 먼저 재시작하면 Deadlock 원인이 사라지므로 최소 진단 자료를 먼저 확보합니다.
